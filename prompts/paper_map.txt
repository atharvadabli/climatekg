SYSTEM

TASK

Build a compact tree of the study settings and comparisons in one land-atmosphere research paper.

A study setting is one complete combination of conditions that the paper directly analyzes. Conditions may include place, period, season or time of day, environmental regime, data source, observation or simulation setup, control or treatment, and values of experimental variables.

Settings are defined by their conditions, not by whether their results differ. Two analyzed combinations are separate settings when any condition that determines applicability differs, even when the paper reports the same effect, a similar effect, or no detectable effect in both.

A child setting inherits every condition from its parent and stores only what changes or becomes more specific. Reading a child together with all its ancestors must identify a scientifically usable setting for the paper's findings.

A comparison is an observed or imposed change between two study settings.

INPUT

You will receive:
- a paper identifier;
- the paper text divided into passages with stable SourceBlock IDs.

HOW TO BUILD THE SETTING TREE

1. Start with conditions shared by most of the paper. Store them in a root setting.
2. Add child settings for each study area, observation or simulation branch, control, treatment, season, time window, environmental regime, and experimental case that the paper analyzes separately.
3. When several named cases share one condition, place that condition in a parent and place their differences in children.
4. Create one child setting for each named experiment, control, scenario, site, or case with a distinct analyzed combination of conditions. A family setting may be their parent.
5. Use `aliases` only for different names that denote the same complete setting. Names with different treatment values, forcing levels, places, periods, or other conditions are separate child settings, not aliases of one group.
6. Treat each analyzed combination of experimental variables as one complete branch. If the paper analyzes a land treatment at two forcing levels, create two complete descendants that inherit the land treatment and differ by forcing level. A setting that says a variable was varied across a list or range is a family parent, not a complete leaf, when the paper evaluates the stated values individually. Create one child for every value actually evaluated. Do not create combinations that the paper did not analyze.
7. Use the fewest nodes that preserve every analyzed combination. Sharing repeated conditions through inheritance makes the tree compact; merging two analyzed combinations because their results are similar does not.
8. Distinguish a condition-defined regime from an outcome-defined group. A season, time window, soil-moisture range, wind regime, model configuration, or other condition used to stratify an analysis is a setting even when it has one reported finding. A group defined only by its observed result is a setting only when the paper subsequently analyzes that group under additional conditions; otherwise represent that result in the cited result passages.
9. Keep settings from cited background studies out of the current paper's tree unless the current paper directly analyzes them as comparison data.
10. Every leaf must be a complete setting under which the paper analyzes findings. Every non-leaf must supply a condition shared by at least two descendant settings. A variable value reused inside complete run names is not a separate sibling leaf.

HOW TO DECIDE WHETHER SETTINGS ARE SEPARATE

1. List the condition dimensions that the paper actually varies or uses to stratify an analysis, such as area, observation or simulation setup, period, season, time of day, treatment, forcing level, or environmental regime.
2. Identify only the combinations that the paper directly analyzes. Do not construct a full cross-product of possible values.
3. Create a complete leaf for every identified combination. Put shared prefixes in parent settings. Expand every explicitly evaluated value, named run, site, period, or regime into its own leaf; do not replace those leaves with one range, list, sweep, ensemble, or sensitivity-group leaf.
4. Keep two combinations separate when any applicability condition differs. The direction, magnitude, significance, or absence of their reported effects does not decide whether the settings are separate.
5. A supported sign reversal, effect-versus-null change, threshold, or major change in applicability confirms that separate condition branches are required, even when each branch supports only one finding.

Example: if one study area is analyzed during an early period and a late period, create a parent for the area and one child for each period. If a second area is analyzed only during the early period, create only that observed area-period branch. Do not invent a late-period branch for the second area. Likewise, if one simulation setup evaluates forcing values 1, 2, and 3, create a shared simulation parent and three value-specific children rather than one leaf labelled "forcing sensitivity from 1 to 3."

For each proposed setting, perform this completeness check:

Read the setting together with all its ancestors. Verify that this combined description states the conditions needed to identify one combination directly analyzed by the paper. If an analyzed area, setup, period, season, regime, treatment, or variable value is missing, add or move the appropriate parent or child setting. A leaf that still contains several individually evaluated values is incomplete. Do this even when two combinations have similar or null results.

HOW TO BUILD COMPARISONS

- Use complete settings as both endpoints.
- Prefer endpoints that hold other relevant conditions fixed when the paper does so.
- When the paper identifies a control, baseline, or reference setting, use it as `from_context_temp_id` and the treatment or changed setting as `to_context_temp_id`.
- When no explicit control is named and the comparison is absence versus presence or non-event versus event, use absence or non-event as `from_context_temp_id`.
- Describe the manipulation or contrast itself, rather than its climatic result.
- Cite passages that establish the comparison and passages containing its reported results.

Use only information stated in the supplied passages. Record unresolved structural uncertainty in `ambiguities`.

OUTPUT

Return valid JSON only. The JSON Schema supplied with this request is authoritative.

Return parent settings before their children in `contexts`.

For each `contexts` item, return:
- `temp_id`: Generate one unique temporary ID.
- `label`: Generate a concise noun phrase, usually 3-12 words, identifying the setting.
- `parent_temp_ids`: List the temporary IDs whose conditions this setting inherits. Use an empty list for a root.
- `split_reason`: Use `null` for a root. For a child, classify why it is separate using exactly one of `separate_reported_finding`, `sign_or_null_reversal`, `misleading_parent_scope`, or `explicit_transition_state`.
- `aliases`: Copy paper-local experiment IDs, scenario names, control names, abbreviations, or alternative names that refer to this same setting. Use an empty list when none are stated.
- `spatial_support`: Use `null` when no location is stated. Otherwise return `kind`, `name`, `geometry`, `enrichable_study_location_name`, and `resolution` as defined below.
- `evidence_block_ids`: Copy the smallest set of SourceBlock IDs that directly establishes the setting.
- `facet_seed_block_ids`: Copy SourceBlock IDs containing environmental, temporal, spatial, model, or experimental conditions for this setting. Use an empty list when none are available.

For `spatial_support`:
- `kind`: Use exactly one of `point`, `patch`, `watershed`, `region`, `climate_zone`, `global`, or `unresolved`.
- `name`: Copy the site, domain, region, or area name stated in the passages.
- `geometry`: Use `null` unless the passages explicitly state enough coordinates for this setting. For one stated site coordinate, return `{{"type":"Point","coordinates":[longitude,latitude]}}`. For four stated domain bounds, return `{{"type":"Polygon","coordinates":[[[west,north],[east,north],[east,south],[west,south],[west,north]]]}}`. Polygon coordinates contain a list of closed rings, so the three opening brackets are required. Use only `Point`, `Polygon`, or `MultiPolygon`, with exactly the keys `type` and `coordinates`.
- `enrichable_study_location_name`: Use `null` when `geometry` is present. When geometry is absent, copy one exact continuous place-name span from the passages, usually 1-8 words. Choose the shortest span that independently identifies the real place analyzed by this paper, including a simulation tied to a real geographic domain. Preserve stated qualifiers only when the shorter name is ambiguous. The returned words must occur in the input. Use `null` for an idealized or global domain, an ambiguous place, or a place mentioned only as background.
- `resolution`: Use `exact` when `geometry` contains exact stated coordinates, `approximate` when it contains explicitly approximate coordinates, `named_region` for a stated local or regional name without geometry, `global` for a global domain, or `unresolved` when the place itself is uncertain.

Spatial coordinates must describe the current paper's analyzed site or domain. A station used only to initialize a model, a place mentioned only in cited background work, one coordinate axis without the other, and a moving track without complete geometry do not establish a Point or Polygon for the setting.

For each `transitions` item, return:
- `temp_id`: Generate one unique temporary ID.
- `from_context_temp_id`: Copy the temporary ID of the starting, reference, or control setting.
- `to_context_temp_id`: Copy the temporary ID of the changed or compared setting.
- `label`: Generate a concise comparison name, usually 2-10 words.
- `aliases`: Copy paper-local names for this comparison. Use an empty list when absent.
- `description`: Generate one sentence, usually 10-50 words, describing what changes between the endpoints.
- `evidence_block_ids`: Copy the smallest set of SourceBlock IDs that establishes the comparison.
- `claim_seed_block_ids`: Copy SourceBlock IDs containing results of this comparison. Use an empty list when none are available.

Also return:
- `context_mention_resolution`: Return an empty JSON object. This input has no preliminary setting inventory.
- `global_claim_seed_block_ids`: Copy SourceBlock IDs containing paper-wide findings that do not belong to one listed comparison.
- `ambiguities`: Write short descriptions of unresolved structural choices. Use an empty list when none remain.
