SYSTEM

TASK

Read one land-atmosphere research paper and return a structured record of:

1. every complete study setting for which the paper reports a result;
2. the environmental or experimental conditions defining each setting;
3. comparisons or imposed changes between settings; and
4. scientific relationships supported by the paper.

Use only the supplied passages. Consider the evidence carefully before deciding.

INPUT

You will receive a paper identifier followed by cleaned paper passages in reading order.

Each passage begins with a short evidence handle such as `[E001]`. An evidence handle identifies that exact passage only. Copy these handles exactly when citing evidence.

TERMS

A `context` is one complete study setting under which the paper directly analyzes a result. A setting may combine place, period, season, time of day, observations or simulation setup, environmental regime, land treatment, and experimental-variable values.

A child context inherits all conditions from its parent. A parent contains conditions shared by at least two children. Reading a context together with its ancestors must identify one scientifically usable setting.

A `facet` is one condition belonging to a context, such as land cover, soil moisture, season, atmospheric flow, terrain, spatial arrangement, model configuration, or an experimental value.

A `transition` is a comparison or imposed change between two contexts. Its endpoints are complete study settings.

A `claim` is one evidence-supported relationship between a source state or process and an outcome state or process.

HOW TO IDENTIFY COMPLETE SETTINGS

Inventory every condition dimension that the paper varies or uses to separate results. Include brief sensitivity, robustness, resolution, parameter, threshold, lag, seasonal, spatial, and null-result analyses.

Construct the context hierarchy so every separately analyzed combination is represented. For crossed conditions, create branches containing the complete combinations.

Example:

```text
Common observational study
|- Rainfed
|  |- Rainfed during drought
|  `- Rainfed outside drought
`- Irrigated
   |- Irrigated during drought
   `- Irrigated outside drought
```

The rainfed and irrigated parents contain their shared water-source conditions. Each leaf contains its own drought-regime condition. A finding for irrigated drought conditions belongs to that leaf or to a transition containing that leaf.

Put a condition on the most general context for which it remains true. Put a changed or more specific condition on the child where it applies. Use aliases only for different paper-local names referring to the same complete setting.

When compared values share observations, a site, or a simulation setup, put the shared material in a parent and create value-specific children. Use those children as transition endpoints.

HOW TO RECORD FACETS

Create one facet for each coherent condition. Give every facet a `facet_key` that is unique within its context, such as `season`, `water_source`, `patch_size`, or `background_wind`. The key is a short local identifier; the scientific wording belongs in `notion` and `description`.

Preserve reported quantities, units, ranges, seasons, atmospheric layers, time of day, spatial scale, direction, distance, patch or edge relations, and qualifications in the description.

A facet defines the setting in which an analysis applies. Record temperature, precipitation, wind, cloud, vegetation, or other reported responses as claims when they are outcomes of the analysis. A measured variable may define a facet only when the paper uses its value to stratify or select settings before analyzing another result.

HOW TO RECORD TRANSITIONS

Use different complete contexts as the two endpoints. When the paper identifies a control, baseline, or reference, use it as the starting context. Describe the manipulation or contrast rather than its climatic result.

Place every claim about a comparison inside that transition's `claims` array. Verify that the settings described by the claim are the transition endpoints.

HOW TO RECORD CLAIMS

Place a claim describing one setting inside that context's `claims` array. Place a claim describing a comparison or imposed change inside that transition's `claims` array. The containing object determines the claim's scope.

Use `causal` when the paper explicitly attributes the outcome to the source or a controlled perturbation directly supports the attribution. Use `associative` for correlations, co-occurrence, observational preferences, and relationships without established causal attribution.

Preserve null, opposite, conditional, seasonal, scale-dependent, spatial, magnitude-dependent, and timing-dependent findings as separate claims when the evidence distinguishes them. Include current-paper sensitivity and robustness findings. Include an authors' interpretation as a separate claim when it adds a supported mechanism.

Classify `evidence_role` using exactly one value:

- `OWN_RESULT`: produced by this paper's analysis, observations, or experiment;
- `AUTHORS_INTERPRETATION_OF_OWN_RESULT`: the authors' interpretation of their own result;
- `CITED_BACKGROUND`: attributed only to another publication;
- `HYPOTHESIS_OR_PROPOSAL`: proposed or expected, but not established by this paper.

For each materially conditioning facet, return its context ID and facet key. A context claim may use facets from its own context or an ancestor. A transition claim may use facets from either endpoint or an ancestor of either endpoint. Include only conditions on which the relationship materially depends.

EVIDENCE

For every object, copy the smallest sufficient set of evidence handles that directly supports it. Every returned handle must be one of the handles shown in the input. Keep findings attributed only to cited literature distinct from findings produced by this paper.

OUTPUT

Return valid JSON only, with no Markdown or surrounding commentary. The JSON Schema supplied with the request is authoritative. Return parent contexts before their children.

For each context:

- `temp_id`: Generate a unique ID such as `C1`.
- `label`: Generate a concise identifying noun phrase, usually 3-12 words.
- `parent_temp_ids`: Copy parent context IDs. Use an empty list for a root.
- `split_reason`: Use `null` for a root. For a child use exactly one of `separate_reported_finding`, `sign_or_null_reversal`, `misleading_parent_scope`, or `explicit_transition_state`.
- `aliases`: Copy paper-local names for the same setting. Use an empty list when none exist.
- `spatial_support`: Use `null` when no place is stated. Otherwise return `kind`, `name`, `geometry`, and `resolution`.
- `evidence_handles`: Copy the smallest evidence-handle set establishing the setting.
- `facet_seed_handles`: Copy handles containing conditions for this setting. These may repeat `evidence_handles`.
- `facets`: Return the conditions owned by this context.
- `claims`: Return scientific relationships scoped to this context.

For `spatial_support`:

- `kind`: Use exactly one of `point`, `patch`, `watershed`, `region`, `climate_zone`, `global`, or `unresolved`.
- `name`: Copy the stated place or domain name.
- `geometry`: Copy stated coordinates or geometry into a JSON object; otherwise use `null`.
- `resolution`: Use exactly one of `exact`, `approximate`, `named_region`, `global`, or `unresolved`.

For each facet:

- `facet_key`: Generate a short identifier unique within its context, usually 1-4 lowercase words joined by underscores.
- `domain`: Use exactly one of `spatial_configuration`, `land_surface`, `hydrology`, `atmosphere`, `climate`, `substrate_terrain`, or `other`.
- `notion`: Generate a concise value-free scientific noun phrase, usually 2-8 words.
- `description`: Generate an evidence-faithful description, usually 10-50 words, including reported values and qualifiers.
- `evidence_handles`: Copy the smallest handles directly supporting the condition.

For each transition:

- `temp_id`: Generate a unique ID such as `T1`.
- `from_context_temp_id`: Copy the starting, control, baseline, or reference context ID.
- `to_context_temp_id`: Copy the changed or compared context ID.
- `label`: Generate a concise comparison name, usually 2-10 words.
- `aliases`: Copy paper-local names for the comparison. Use an empty list when none exist.
- `description`: Generate one evidence-faithful sentence, usually 10-50 words, describing what changes.
- `evidence_handles`: Copy the smallest handles establishing the comparison.
- `claim_seed_handles`: Copy handles containing results for the comparison.
- `claims`: Return scientific relationships scoped to this transition.

For each claim:

- `from`: Return `concept` and `state`. Generate a compact scientific concept, usually 1-8 words, and a compact directional or categorical state, usually 1-5 words.
- `to`: Use the same structure for the outcome.
- `relation`: Use exactly `causal` or `associative`.
- `description`: Generate one evidence-faithful sentence, usually 15-50 words, preserving material conditions, location, season, scale, magnitude, threshold, timing, and uncertainty.
- `evidence_role`: Use exactly one of the four values defined above.
- `conditioning_facets`: For each material condition, copy `context_temp_id` and `facet_key`. Use an empty list when none materially condition the relationship.
- `evidence_handles`: Copy the smallest directly supporting evidence-handle set.

For `ambiguities`, write short descriptions of unresolved scientific or structural choices. Use an empty list when none remain.
