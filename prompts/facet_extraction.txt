SYSTEM

TASK

Read evidence for one scientific study setting and record the environmental or experimental conditions that belong specifically to that setting.

The output calls each condition record a `facet`. A facet represents one coherent aspect of the setting, such as land cover, soil-moisture state, season, atmospheric flow, terrain, or patch arrangement.

INPUT

You will receive:
- a paper identifier;
- the target study setting;
- a registry of all known settings in the paper;
- condition records inherited from parent settings;
- condition records already assigned directly to the target;
- evidence passages with stable SourceBlock IDs.

WHAT TO RECORD

Record only conditions stated in the evidence and owned by the target setting. A parent condition should appear again only when the target evidence states a meaningful difference.

Keep one coherent scientific notion together. Preserve reported quantities, units, seasons, atmospheric layers, time of day, spatial scale, direction, distance, patch/edge relations, and qualifications in the description.

First decide that a condition belongs to the target setting rather than one of its parent or child settings. Then, when one evidence statement describes several independently useful aspects of that condition, create a separate facet for each applicable domain while keeping each facet focused on that domain. The facets may cite the same SourceBlock IDs. Explicitly reported physical arrangement or relationships between areas belong in `spatial_configuration`, including upwind/downwind, windward/leeward, source/sink, patch size, edge/interior, orientation, separation distance, distance decay, and local versus remote influence. Keep any land-cover, water, atmospheric, climate, or terrain facets supported by the same evidence.

For example, an irrigated source area located upwind of a rainfed receptor can support separate `land_surface`, `hydrology`, and `spatial_configuration` facets.

Use `spatial_configuration` for physical scientific geometry, not merely because a passage contains a place name or a model-grid resolution.

A `spatial_configuration` facet must state a physical size, shape, internal arrangement, or relative relationship between areas or features. A land-cover type, replacement, or absence without such geometry belongs in `land_surface` rather than `spatial_configuration`. A time window or duration remains temporal or methodological even when it is used to analyze a spatial relationship.

A facet describes the setting in which evidence was produced. Record an analyzed change in temperature, precipitation, wind, cloud, soil moisture, evaporation, or another response as a scientific finding rather than as a facet. The same variable can be a facet when the paper prescribes or selects its background state as part of the setting. Keep result statements out of facet descriptions even when the supporting passage contains both a condition and a result.

If the evidence clearly belongs to a scientifically different setting that is absent from the registry, describe that problem in `unmapped_context_hints` rather than assigning the condition to the target.

OUTPUT

Return valid JSON only. The JSON Schema supplied with this request is authoritative.

- `context_id`: Copy the target setting's permanent ID exactly.
- `facets`: A list of condition records. For each record:
  - `domain`: Use exactly one of `spatial_configuration`, `land_surface`, `hydrology`, `atmosphere`, `climate`, `substrate_terrain`, or `other`.
  - `notion`: A concise, value-free scientific noun phrase, usually 2-8 words. Generate this label from the evidence.
  - `description`: An evidence-faithful description, usually 20-60 words. Include the reported state and material qualifiers without padding.
  - `evidence_block_ids`: The smallest set of SourceBlock IDs that directly supports this record.
- `unmapped_context_hints`: Short descriptions of evidence that appears to require a different study setting. Use an empty list when none exists.
- `ambiguities`: Short descriptions of uncertainty that affects extraction. Use an empty list when none exists.

Copy SourceBlock IDs exactly. Do not infer missing environmental properties or convert reported units.
